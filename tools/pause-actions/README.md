# Pause Actions

Клиентское меню этой сборки: mod ID `lanmc_pause_actions`, версия 1.0.1. На месте штатной кнопки «Настройки мира» находится «Открыть для сети» до публикации и «Жалобы» после неё. Для подключённого участника без встроенного сервера сразу доступны жалобы. Прежний `lanmc_world_menu` полностью отменён и остаётся только исторической exact-hash записью для удаления старой копии при обновлении.

## Поведение

Компонент не удаляет и не создаёт кнопку заново. Required client Mixin добавляет getter/setter к `Button.onPress`; обработчик NeoForge меняет callback и подпись того же объекта `Button`. Штатная сетка продолжает владеть тем же объектом: координаты, размеры, порядок обхода, отрисовка, narration и фокус сохраняются. Перед отрисовкой обновляется подпись только собственной кнопки; глобальных таблиц объектов нет.

До загрузки классов параметр самой сборки в `launcher/jvm-args.txt` устанавливает `minecraft.portable.identity.pauseLanRowEnabled=false`. Это отключает прежнее добавление отдельной широкой строки адаптером. Общий лаунчер уже поддерживает переопределение `-D` параметрами сборки; новый C# код, привязки к имени сборки и новый EXE не добавляются. Первая строка с настройкой Log4j сохранена.

Нажатие заново проверяет действительное состояние сервера. Для непубликованного собственного мира вызывается только `IntegratedServer.publishServer(MultiplayerScope.LAN, port)`. Это двухаргументный нативный метод, сохраняющий существующие команды и режим мира. TCP listener активирует установленный Steam-мост e4steam. Успех и ошибка используют штатные локализованные сообщения, после попытки закрывается пауза. Экран `WorldOptionsScreen` не создаётся ни на успешном пути, ни при ошибке. Для уже опубликованного мира и гостя открывается штатный `SocialInteractionsScreen(parent)`.

Таким образом, создание мира сохраняет штатный выбор читов и правил, а меню созданного мира не предлагает их менять. Сохранённые настройки мира не переписываются этим компонентом. Уже разрешённые при создании команды не отключаются.

## Runtime-инъекция и Safety

Авторские JAR не перепаковываются. Однако runtime `Button.class` отличается: Sponge Mixin снимает `final` с поля `onPress` и добавляет два accessor-метода. Запись выполняется только для штатной кнопки `options.worldOptions.button` на `PauseScreen`; действия остальных кнопок не заменяются. Это адресная клиентская инъекция, а не утверждение о неизменном runtime-поведении Minecraft при прежнем SHA исходного JAR.

Платформа остаётся Minecraft 26.3 / NeoForge 26.3.0.99. EMI, Iris и Sodium сохраняют исходные версии и SHA256. Установленный общий e4steam `native-ui.1` также не меняется и не включается в pack assets. Снимок исходников до нового исправления: `baseline-641b88a.json`.

Проверка необходимости Safety: новая логика меняет только клиентский callback и запускает штатную публикацию/экран жалоб. Нет новых terrain/chunk/palette/inventory путей, caster/owner-механик, отложенных игровых действий или изменения разрешений команд/режима. Другие моды и их Safety-профили не меняются. Отсутствие таких вызовов проверяется также в байткоде компонента и нативного пути публикации.

## Публикация и будущие версии

Полное правило принадлежит сборке: её JAR, исходники и JVM-данные обновляются одним manifest. Самостоятельного проекта CurseForge/Modrinth у встроенного компонента нет; официальные описание, исходники и загрузка находятся в этом репозитории. В библиотеке используется этот источник.

В `contract.json` нет проверки `Minecraft == 26.3`. Сборщик получает версии из `portable-pack.json` и компилирует компонент против официальных API. Перед публикацией CI безусловно проверяет воспроизводимую сборку, настоящий Sponge Mixin, нативные кнопки и действия и метаданные пакета. Генератор отдельно требует компонент и ровно один отключающий широкую строку JVM-параметр. Удаление JAR вместе с lock-записью или возвращение старого helper отклоняется.

При обновлении, например, до 26.4 несовместимость должна остановить публикацию до исправления компонента. Это обязательность правила, а не заявление о проверенном запуске ещё не выбранной будущей платформы. Потребуется также совместимый Steam-транспорт, его текущий диапазон не расширяется молча.

## Проверки

Нужны Python 3.12+ и JDK выбранной платформы, сейчас Java 25:

```powershell
$env:JAVA_HOME = 'C:\Tools\jdk-25.0.2'
python -B tools/pause-actions/build.py --output .cache/pause-actions/rebuilt.jar
python -B tools/pause-actions/verify_native.py --jar mods/lanmc-pause-actions-1.0.2.jar
python -B -m unittest discover -s tools -p test_pause_actions.py
```

Сравните результат с поставляемым JAR побайтно. CI выполняет это автоматически. Зависимости скачиваются только из официальных источников с проверкой хешей. Проверенный официальный NeoForge installer и его processors подготавливают пропатченный клиент исключительно в частном `.cache/pause-actions/native-runtime`; Minecraft client/server main не запускается. В classpath первым идёт именно этот patched JAR, затем ванильный fallback и зависимости. Входные хеши и полученный JAR закрепляются локальным fingerprint, повреждённый кеш пересоздаётся. Поставляемый JAR содержит только собственные классы, контракт, mixin-конфигурацию, metadata и MIT license, без чужих библиотек.

Нативная проверка применяет настоящий выбранный Mixin к пропатченному NeoForge `Button.class` и исполняет сгенерированные accessor-методы. Подмена его ванильным классом отклоняется. Для текущего 26.3 / NeoForge 26.3.0.99 размер исходного класса 4265 байт, SHA256 `a3c5bf37aac82e360913080768fdf2005506afb9a0124e3466ee0a4d1bf6de7a`; класс проверен против действительно установленного JAR. Границы тестовых замен и проверяемых callback перечислены в `probe/README.md`. Новый клиент/renderer/мир и пользовательские игровые данные для этих проверок не запускаются и не используются.

## Обнаружение опубликованного мира

Версия 1.0.1 после успешного двухаргументного native publish ровно один раз вызывает `SteamWorldDiscovery.published(minecraft, server, port)`. Мост отражением обращается к уже имеющемуся `PortableSteamDiscoveryHooks.published(Object,Object,int)` лаунчера: сначала через bootstrap loader, куда настоящий агент помещает hooks, затем через game/system loaders. Класс и сигнатура API закреплены в `contract.json`; точных версий Minecraft и e4steam в этом интеграционном пути нет. Это уведомление, не повторная публикация и не вызов старого `autoPublish`.

Существующий helper асинхронно получает ник из текущего `User` и имя текущего мира, ждёт готовности лобби той же hosting generation и записывает `lanminecraft_player`, `lanminecraft_world`, `lanminecraft_display=1`. Именно эти поля требует игровой поиск. При отказе или исключении native publish уведомление не отправляется. Ошибка/отсутствие helper сохраняет успешную публикацию, сообщения, закрытие меню и жалобы; выводится одно ограниченное предупреждение без имён, ID лобби и стека. Сам транспорт и его API здесь не копируются и не меняются.

Снимок до замены: `baseline-ffcd677.json`. Заменён только собственный Pause Actions 1.0.0 (11473 байт, SHA256 `74ae31bb88c6e486f40dd5ee2ab17ac8af5edd672a7c87a2094f3c37ed2614c8`); новый exact SHA находится в active lock и `verification.json`. Старый JAR остаётся только в `legacyFiles` для точного удаления при обновлении. Mod ID `lanmc_pause_actions` сохранён, игровых registry ID компонент не создаёт. EMI/Iris/Sodium, конфиги, JVM-параметры и пресет не изменяются. Для текущей доставки используется централизованный e4steam `native-ui.2`; это наблюдение проверки, не требование новой копии транспорта в сборке.

Safety: добавлен только вызов существующего издателя описания Steam-лобби. Нет новых terrain/chunk/palette/inventory путей, caster/owner-разрешений или отложенных изменений мира. Штатный двухаргументный publish и права команд/режим мира не меняются; обновление gameplay Safety не требуется.

## Сохранение при обновлениях

При переносе авторских файлов сохраняют весь `tools/pause-actions`, его исходный и встроенный контракт, обязательный компонент в active lock, `launcher/jvm-args.txt` и безусловный шаг native-проверки в workflow. Генератор сравнивает интеграционный контракт с независимым эталоном и требует класс моста; согласованное удаление полей из обеих копий контракта и обновление SHA в lock не обходят проверку. Нативный тест исполняет packaged callback, проверяет адресный вызов после успеха, точный server/port и отрицательные случаи. Удаление вызова или перенос его до успеха останавливают проверку. Будущая несовместимая платформа должна остановить публикацию, а не молча вернуть прежнее поведение.

После изменения Minecraft/NeoForge пересобрать компонент против версий `portable-pack.json`, повторить native Mixin/actions/metadata serializer, управление, логирование и упаковку. После изменения централизованного e4steam отдельно повторить handoff на актуальном launcher helper/транспорте и проверить запись/чтение описания, версию/протокол и hosting generation. Не отключать guard и не подменять проверку фальшивым PASS. Отсутствие точного version pin сохраняет интеграцию при совместимых обновлениях; оно не удостоверяет ещё не выбранный будущий API.

Дополнительная изолированная проверка установленного helper:

```powershell
python -B tools/pause-actions/verify_discovery_bridge.py --agent <actual-portable-identity-adapter.jar> --jar mods/lanmc-pause-actions-1.0.2.jar --cache-dir <private-native-cache> --report .cache/discovery-bridge.json
```

Она использует байты packaged моста и реального bootstrap helper с явно обозначенными in-memory границами игровых/Steam-служб. Это проверка handoff и metadata, не соединение двух Steam-аккаунтов, запуск renderer или личного мира. Последние проведённые проверки и их границы фиксируются в `verification.json`.
