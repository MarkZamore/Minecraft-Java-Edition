# Minecraft 26.3

Обычный Minecraft 26.3 для лаунчера LANMinecraft с просмотрщиком предметов и рецептов EMI и поддержкой собственных шейдеров через Iris/Sodium. Миры, личные настройки и игровые данные в поставку не входят. Официальный клиент Mojang лаунчер получает по версии из `portable-pack.json`.

| Компонент | Закреплённая версия |
| --- | --- |
| Minecraft | 26.3, актуальный официальный release на 28 октября 2026 года |
| NeoForge | 26.3.0.99 |
| EMI | 1.1.24-e7edb3a+26.3+neoforge, авторский build+62, Alpha |
| Iris | 1.11.7+mc26.3, NeoForge, Release |
| Sodium | 0.9.3-beta.1+mc26.3, NeoForge, Beta; обязательная зависимость Iris |
| Pause Menu Actions | 1.0.2, встроенное клиентское меню LAN и жалоб |
| Загружаемых mod ID в репозитории | 4 |

EMI взят из того же [неофициального порта link-fgfgui](https://www.curseforge.com/minecraft/mc-mods/emi-unofficial-port-unstable), что использовался в прежней сборке 26.2. Обновлён именно этот проект: [файл 9242955](https://www.curseforge.com/minecraft/mc-mods/emi-unofficial-port-unstable/files/9242955), [исходный коммит e7edb3a](https://github.com/link-fgfgui/emi/commit/e7edb3aa4d7619eaaa03e01084fe01bb3db567e7). Автор пометил оба использованных порта как Alpha; это не заявление о стабильном канале мода.

Для совместной игры лаунчер отдельно устанавливает закреплённый [e4steam](https://www.curseforge.com/minecraft/mc-mods/e4steam) подходящего загрузчика. Транспорт не дублируется в `mods` этого репозитория и не входит в счётчик четырёх загружаемых компонентов. Любой участник может открыть свой встроенный мир через существующий лаунчер.

## Меню созданного мира

В той же ячейке, где Minecraft 26.3 показывает «Настройки мира», находится «Открыть для сети». После публикации мира эта кнопка становится «Жалобы»; для подключённого участника она сразу открывает жалобы. Отдельная широкая строка LAN не добавляется. Кнопка сохраняет свой штатный объект, расположение, размер и порядок фокуса, в том числе при изменении размеров окна.

Открытие LAN использует штатный двухаргументный метод сервера и не меняет сохранённые читы, режим игры и правила. Экран настроек мира при этом вообще не создаётся, включая ошибку публикации. Выбор правил при создании мира сохраняется.

После успешного открытия LAN Pause Menu Actions уведомляет существующий обработчик Steam discovery лаунчера. Он публикует имя текущего игрока и мира в готовом Steam-лобби, чтобы мир появился в игровом списке мультиплеера. Прежний прямой вызов сервера обходил этот шаг: приглашение Steam работало, но список отбрасывал лобби без описания. Обработчик вызывается через его общий Object-only API без закрепления версии e4steam; транспорт по-прежнему доставляет только лаунчер. Отсутствие обработчика не отменяет открытый мир. Контракт и обязательные проверки публикации сохраняют интеграцию при обновлении платформы; порядок дальнейшей проверки описан в [Pause Menu Actions](tools/pause-actions/README.md).

Прежний компонент `lanmc_world_menu` отменён; он не входит в активный состав. Исправление находится в самой сборке: [Pause Menu Actions](tools/pause-actions/README.md) и её `launcher/jvm-args.txt`. Новый EXE и новые правила в C# лаунчера не нужны. При обновлении игры публикация проверяет реальный Mixin, нативную кнопку и действия, сохранение обязательного компонента и параметра меню.

## Обновление существующей сборки

Minecraft 26.3 продолжает прежнюю карточку: стабильный ID библиотеки остаётся `minecraft-26-2`, отображаемое имя и папка становятся `Minecraft 26.3`, репозиторий поставки — `MarkZamore/Minecraft-26.3`. Новая версия лаунчера переносит старое расположение профиля и получает текущий `pack-latest`; личный `options.txt` не заменяется при загрузке пресета.

Старый EMI для 26.2 удалён из активной поставки. `legacyFiles` манифеста содержит только его точные прежние размер и SHA-256 для распознавания устаревшего файла. Историческая запись не является ещё одним загружаемым модом. Неизвестные изменённые файлы нельзя считать проверенной старой копией по одному имени.

Точные замены, хеши, проверка происхождения и границы проверки приведены в [tools/UPGRADE-26.3.md](tools/UPGRADE-26.3.md). Первоначальный протокол обновления не включал игровой запуск; новый прогон с поддержкой шейдеров описан отдельно в `tools/SHADERS.md`, включая ограничение завершения JVM. Совместимость старых миров без преобразования или потерь этим выпуском не удостоверена.

## Публикация и библиотека

[Текущий состав QA и границы статического аудита](tools/QA.md) описывают проверки именно этой сборки и сохранённые отрицательные сценарии.

Push в `main` запускает `.github/workflows/publish.yml`. Workflow проверяет пресет, exact-hash состав, границу активных и исторических файлов и библиотечные метаданные; публикует payload перед `pack-manifest.json` и затем удаляет больше не используемые release assets. Существующий релиз `pack-latest` обновляется на месте.

`tools/distribution-lock.json` закрепляет активные EMI, Iris, Sodium и Pause Menu Actions, их mod ID и авторские источники. `tools/upgrades/minecraft-26.2-baseline.json` хранит отдельный снимок прежнего коммита, а `tools/legacy-files.json` — точные записи для миграции. `library/content.json` задаёт карточку; `library/mod-pages.json` связывает каждый мод со страницей фактически поставляемого проекта. Генератор отклоняет отсутствующую ссылку и собирает отдельный content-addressed архив библиотеки.

## Управление

`launcher/controls-preset.txt` содержит все 62 ванильных назначения 26.3 и четыре назначения Iris для OpenGL. Меню шейдеров открывается на J, переключение на K, отладочная перезагрузка на R, wireframe оставлен неназначенным. Сканер читает реальные `Options` и таблицу сериализованных имён `InputConstants$Type`: переход на SDL не интерпретируется через старые номера GLFW. Сохранена привычная раскладка и добавлено штатное F3+X для переключения улучшенной прозрачности; сам пресет не меняет этот графический параметр. Собственные R/U и другие сочетания EMI остаются в его `config/emi.css`. Проверка и обновление описаны в [tools/keybinds/design.md](tools/keybinds/design.md).

## Собственные шейдеры

В поставку добавлены только [Iris](https://www.curseforge.com/minecraft/mc-mods/irisshaders) и требуемый им [Sodium](https://www.curseforge.com/minecraft/mc-mods/sodium). Готовых shaderpack ZIP, выбранного по умолчанию набора и принудительных ограничений дальности нет. Личный набор можно добавить в папку `shaderpacks` своего игрового экземпляра через кнопку открытия папки в меню Iris, затем выбрать его в списке. Iris этой версии поддерживает шейдеры через OpenGL; при Vulkan показывает предупреждение и предлагает использовать OpenGL. Бэкенд и личные графические настройки поставка не переписывает.

Точные источники, обязательная зависимость и границы проверки: [tools/SHADERS.md](tools/SHADERS.md).

## Ограниченная диагностика сетевых исключений

`config/log4j2.xml` сохраняет полные стеки четырёх пойманных сетевых исключений
`net.minecraft.network.Connection` в существующем `logs/latest.log`. Обычные
INFO/WARN/ERROR сохранены; остальные DEBUG, включая поток пакетов, отклоняются.
Отдельный `debug.log` не создаётся. Прежние пределы ротации сохранены: 32 МБ,
пять архивов и удаление архивов старше семи дней. Здоровое соединение не добавляет
этих диагностических событий. Это диагностика, а не исправление обрыва связи.

Конфиг закреплён как точный `config/log4j2.xml` в `launcher/pack-owned.txt`;
остальные личные конфиги этим правилом не охвачены. Перед заменой отличающейся
личной копии обычное обновление лаунчера сохраняет её в PackConflicts. Выбор
конфига уже находится в `launcher/jvm-args.txt`; новых правил C# при запуске нет.

После ручного переноса новой авторской версии сохраняют `config/log4j2.xml`,
`launcher/jvm-args.txt`, `launcher/pack-owned.txt`, `tools/network_logging_policy.py`
и `tools/network-logging-policy.json`. Затем в независимой исходной копии выполняют:

```text
python -B tools/network_logging_policy.py prepare --pack .
python -B tools/network_logging_policy.py verify --pack .
python -B -m unittest discover -s tools -p test_logging_policy.py
```

`prepare` применяется только при подготовке исходников, сохраняет остальные
JVM-параметры и обновляет квитанцию политики. Генератор поставки проверяет XML,
точный выбор JVM, ownership и квитанцию как перед упаковкой, так и в режиме
проверки. Удаление или повреждение правила останавливает публикацию, а не
возвращает молча прежнее логирование. Автоматическое обновление авторской сборки
без подготовки исходников здесь не заявляется. Новые версии игры и загрузчика
требуют повторной проверки настоящего сетевого обработчика.

[Подтверждения](tools/network-logging-proof/README.md) содержат точные SHA256
нативных классов и проверки фильтра настоящими Log4j 2.19.0, 2.22.1 и 2.26.0.
Игровой прогон этим изменением не выполнялся. JAR, графика, механики и пути
изменения мира не меняются; новая проверка Safety не требуется.
